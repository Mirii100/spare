How it works

Rules the app follows

  • Every action saves to the phone first, so nothing is lost when the signal drops or the phone restarts.
  • Nothing is edited in place. Sales, payments, returns, receipts, and adjustments are added as new records.
  • Stock and balances are calculated from those records, so you can see why stock is 48.
  • Each record has a unique ID made on the phone. The server ignores repeats, so one offline sale is exactly one sale.
  • Voice only fills in the confirm screen. You always review before saving.

Sale flow

SpeakthenReviewthenConfirmthenDone

On confirm, the sale creates stock movements (-), updates the customer ledger, records payments by method, and stores cost and price for profit.

Phone databasethenSync queuethenCloud

The sync queue retries until the server confirms. The badge shows "All data synchronized" or "7 waiting to sync".

Proposed stack

  • App: installable web app (PWA) or React Native, with a local SQLite database and sync queue
  • Voice: on-device speech recognition for mixed Swahili and English, then a parser for customer, item, quantity, price, and payment
  • Server: Postgres (for example Supabase) with role-based permissions and automatic daily backups
